# kb-starter · 一键建个人知识库，并让它自己长

> 我用 Obsidian 攒了 4 个月、570 多篇笔记，一直以为它在照着 Karpathy 说的“自生长知识库”慢慢长。用这个工具给它做了一次体检才发现：298 份原文从来没有被任何一张知识卡片引用过，55 张卡片缺少让 AI 想起它们的说明。它没在长，只是在变大。kb-starter 就是为了解决这件事做的。

## 30 秒上手

```bash
npx skills add Lucas0ng/kb-starter -g
```

然后对 AI 说：“帮我把 `~/Downloads/研究资料` 整理成知识库，建在 `~/知识库`。”它会先给你看方案表，你确认后才动手。其他安装方式见[用哪个 AI：三档工具](#用哪个-ai三档工具)。

*English: kb-starter is an Agent Skill (Claude Code, Codex, Cursor and more) that turns scattered local files into a layered personal knowledge base, distills them into knowledge cards, keeps a card index as the AI's memory, lets the AI list the knowledge it is missing, and reports whether the base is actually growing. Templates and prompts are in Chinese.*

## 它会做什么

把散落在电脑里的论文、实验记录、会议录音、课件、截图一股脑交给 AI，它会：

1. **建库**：按“输入 / 理解 / 方法 / 产出”分层整理成知识库。原件只复制不移动，执行前先给你看方案表。
2. **蒸馏**：把材料写成知识卡片。论文写成文献卡片，会议和聊天里定下的事写成决策卡，踩过的坑写成问题卡，还有 SOP、人物卡、教训卡和概念节点。科研和日常工作都适用。
3. **想得起来**：从所有卡片自动生成一份知识索引，AI 每次开工先读它，知道自己“已经知道什么”。
4. **主动要知识**：开始一件大事前，AI 读完知识库后，列出自己还缺哪些知识、去哪补。做任务时缺知识，它会记进缺口清单，而不是凭空编。
5. **入库、回流、体检**：新文件自动去重归位；每次任务结束把结论写回卡片；每周体检，看知识库是在“生长”还是只在“变大”。
6. **换 AI 不用重新建**：自动生成 `AGENTS.md`（Codex、Cursor、Trae 读）、`CLAUDE.md`（Claude Code 读），网页版 AI 用一键生成的粘贴包。

原型来自一个真实使用了 4 个月、570 多篇笔记的研究生 Obsidian 知识库。

## 知识库要有知识：蒸馏、记忆、补缺

整理好的文件夹只是材料，**知识在卡片里**。kb-starter 把“蒸馏”做成内置能力，不依赖任何外部 skill：

| 材料 | 蒸馏成 | 记什么 |
|---|---|---|
| 论文、标准、报告 | 文献卡片 | 实际证明了什么、关键条件和数字（带页码）、证据边界、和我的关系 |
| 会议、聊天、邮件 | 决策卡 | 定了什么、谁定的、原话、为什么、什么情况下重新考虑 |
| 故障、踩过的坑 | 问题卡 | 症状、原因、解法、以后怎么避免 |
| 反复做的事 | SOP | 现行做法置顶，旧口径放页末 |
| 打交道的人 | 人物卡 | 负责什么、沟通偏好、已定的事（只记工作相关） |
| 阶段复盘 | 教训卡 | 下次怎么做、适用范围 |
| 反复出现的概念 | 概念节点 | 一句话、关键事实（每条带来源）、边界和争议 |

**AI 怎么想起过去的知识？** AI 没有跨对话的记忆，知识库就是它的记忆，关键是让它在需要时找得到。每张卡片头部都写三个字段：「一句话」（说了什么）、「用于」（什么时候该想起它）、「来源」（原文链接）。`kb.py index` 把它们汇总成一份知识索引，每张卡占一行。`AGENTS.md` 规定 AI 开工先读这份索引，再根据「用于」把当前任务和过去的卡片对上。这和 Claude Code 自己的记忆机制是同一个思路：常驻一份小索引，细节用到时再读。

**AI 怎么主动补缺？** 分两种情况：

- **做任务时**：发现缺知识，就记进 `缺口清单.md`（缺什么、哪个任务需要、建议去哪补），不凭空补。
- **开始一件大事前**：用内置的缺口自检提示词，让 AI 列出三类缺口：库里有原文但没蒸馏的、库里没有需要补资料的、证据弱或互相矛盾的。`kb.py gaps` 先机械地找出“没有任何卡片引用过的原文”，并按“被其他笔记提到的次数”排序。

**怎么知道它真的在长？** 变更日志每行带类型标签（`[入库]` `[蒸馏]` `[回流]` `[缺口]` `[体检]` `[决策]` `[整理]`），`kb.py stats` 按周统计，并给出一句判断，例如“最近两周没有新增卡片，也没有蒸馏或回流：知识库只在变大，没有在生长”。没打标签的旧日志会按关键词推断类型，所以已有的库也能直接看。

## 和同类项目有什么不同

Karpathy 的 llm-wiki 思路（2026-04 发布的 gist）出来后已有不少实现，它们大多假设你从零开始、手动把资料放进 `raw/`。kb-starter 解决的是前一步和后一步：

- **前一步**：你已经有一堆乱放的文件。规则先分（文件名、扩展名、DOI、EXIF、文档标题），只有判断不了的才交给 AI 读首页。测试中约九成文件由规则直接处理，几百个文件也不会烧太多 token。
- **后一步**：建完以后靠“回流 + 体检”持续生长，而不是只会越堆越多。
- **面向中文科研**：文献卡片、实验记录（原话 / 实测 / 计算 / 推断分栏）、假设台账、SOP 现行口径置顶、项目总览只写现在。
- **规则写在知识库里**：分层规则、回流规则、体检提示词都生成在知识库自己的文件里。即使换了一个没装本 skill 的 AI，它照着 `AGENTS.md` 也能按同样的规矩干活。

## 怎么保证：原件不坏、一个不漏、整理完不乱

建库本质上就是一次文件整理，最怕的是三件事：原件被改坏、有文件悄悄没进来、整理完照样乱。kb-starter 对前两件做成**可以验证的硬保证**，第三件靠规则加每周体检持续维持。

**原件不坏。** 只复制、不移动、不改名、不删除。需要起新名字的（`IMG_4521.jpg` 这种）只改知识库里的副本，资料索引里保留原名。每次入库后核对原件的修改时间，`verify --full` 会重算原件哈希。

**一个不漏。** 来源里的每个文件在方案表里都有一行、一个去向和一条理由，包括跳过的：

- 隐藏文件夹、`node_modules` 这类依赖文件夹、符号链接文件夹各记一行，写明里面有几个文件；
- iCloud 还没下载到本机的文件（占位文件）、没有读权限的文件标成“无法读取”，放在方案表最上面，提醒你处理；
- 还有文件没判断完（“待AI”）时，脚本拒绝执行。

复制完自动对账，生成这样一张对账单，等式不成立、副本哈希不一致、扫描后来源多了或少了文件，都会报错：

```
- 来源共 50 个文件 = 复制 39 + 登记 0 + 已入库 0 + 跳过 7 + 无法读取 2 + 未展开文件夹内 2
- 副本校验：39/39 个与原件哈希一致
- 原件检查（比对修改时间）：均未改动
- 扫描后新增 0 个，消失 0 个
```

**整理完不乱。** 固定的分层和项目子目录是骨架，另外有四条规则：

- 同一文件的多个版本（`v1/v2/v3`、`修改版`、`终稿`、`(1)`）只留最新的在原处，其余放进同目录的 `历史版本/`，不删除；
- 不同文件夹里的同名文件（两个 `1.jpg`）各自保留来源文件夹名，不会变成 `1 (2).jpg`；
- 看不出内容的文件名，AI 看过内容后可以起入库名，格式 `YYYYMMDD_内容`；
- 入库时出现知识库里没有的项目名，会提示“可能就是「电解液」”，避免同一个课题分裂成好几个文件夹。

用久了会不会重新变乱，看每周体检的“整洁度”一节：根目录多出的文件、`09_待定` 积压多久了、超过 150 个文件的文件夹、同一文件夹里并存的多个版本、INBOX 积压。

## 用哪个 AI：三档工具

不同 AI 能做的事不一样。kb-starter 把规则写进了知识库自己的文件，所以三档工具都能用，只是自动化程度不同。

**第一档：能装 skill、能读写本地文件**（全部功能）

最省事的是一行命令，支持 Claude Code、Codex、Cursor 等 30 多种工具（`-g` 表示装到用户目录，所有项目可用）：

```bash
npx skills add Lucas0ng/kb-starter -g
```

Claude Code 用户也可以作为插件安装，以后用 `claude plugin update` 拿到新版本：

```bash
claude plugin marketplace add Lucas0ng/kb-starter
```

```bash
claude plugin install kb-starter@kb-starter
```

不想用命令行时，下载仓库，把 `skills/kb-starter/` 文件夹复制到对应位置：

| 工具 | 放到哪 |
|---|---|
| Claude Code | `~/.claude/skills/kb-starter/` |
| Claude 桌面版 | 把 `skills/kb-starter/` 打成 zip，在 Skills 设置里上传；用桌面版打开知识库文件夹 |
| Codex | 知识库下的 `.agents/skills/kb-starter/` |
| Trae | 切到 SOLO Coder 模式，放进项目的 `.trae/skills/kb-starter/`（据社区教程，普通对话模式不触发 skill） |
| 豆包电脑版 | 据媒体报道，专业版的办公任务模式支持技能，也能在授权后操作本地文件；具体的导入方式以豆包官方说明为准（作者尚未实测） |

装好后直接说“帮我把 `~/Downloads/研究资料` 整理成知识库”即可。

**第二档：能读写本地文件夹，但装不了 skill**

在知识库文件夹里打开它，告诉它“先读 AGENTS.md，按里面的规则工作”。建库那一步的自动分类和对账用不了，但蒸馏、回流、缺口记录、日志标签都写在 `AGENTS.md` 和 `知识库说明.md` 里，照做即可。知识索引可以让它手动维护，或者偶尔用第一档工具跑一次 `kb.py index`。

**第三档：只能聊天**（豆包网页 / App、DeepSeek、Kimi 网页、ChatGPT 网页等）

- **读知识库**：用第一档工具生成粘贴包（`99_工作区/粘贴包/`），整份粘贴到对话开头。粘贴包里有导航、项目总览、假设台账和知识索引。
- **蒸馏**：把 `02_方法论库/写作模板/` 里对应的模板和原文一起发给它，让它按模板输出卡片，你再复制回知识库对应文件夹，并在变更日志里记一行 `[蒸馏]`。
- **缺口自检**：把粘贴包和 `缺口自检提示词.md` 里的那段提示词一起发过去。

需要 Python 3.9+（第一档），不需要安装任何第三方包。装了 `pdftotext`（poppler）时 PDF 识别更准。

## 怎么用

直接对 AI 说：

- “帮我把 `~/Downloads/研究资料` 整理成知识库，建在 `~/知识库`。”
- “把这几篇新下载的文献入库，然后精读第一篇。”
- “把今天组会的记录蒸馏一下。”／“把这次排查的问题记成问题卡。”
- “我下周要写综述第 4 节，先自检一下知识库还缺什么。”
- “给知识库做个体检。”／“执行体检。”（勾选完建议之后）
- “知识库最近有没有在长？”
- “生成一个粘贴包，我要在豆包里用。”

想每周自动体检，用宿主的定时任务（Claude 的 scheduled tasks、Claude Code 的 `/schedule` 或系统 cron）每周触发一次“给知识库做体检”。

## 建出来的知识库长什么样

```
知识库/
├── AGENTS.md / CLAUDE.md        任何 AI 的入口
├── 知识库导航.md                 总地图
├── 知识索引.md                   AI 开工先读：每张知识卡片一行（自动生成）
├── 知识库说明.md                 新文件放哪、卡片怎么写、回流规则（唯一规则来源）
├── 知识库变更日志.md             每行带类型标签，用来统计增长
├── <项目>_总览.md                只写“现在”：当前状态 + 现行文件表
├── 00_原始资料/                  A 输入层，只读（论文、实验、会议、剪藏、课程、个人笔记、待定）
│   └── 资料索引.md               自动生成
├── 01_知识提炼/                  B 理解层：概念节点，文献、决策、问题、教训、人物卡片，
│   └── 研究问题/                 假设台账、缺口清单
├── 02_方法论库/                  C 方法层（SOP、卡片模板、体检和缺口自检提示词）
├── 03_研究输出/                  D 产出层（论文草稿、汇报 PPT、报告）
├── 04_复盘日记/体检/             每周体检报告
├── 99_工作区/                    代码、粘贴包、过程文件
└── .kb/                          清单（哈希去重）、历次方案表、不入库记录
```

## 目录

```
.claude-plugin/             Claude Code 插件清单（plugin.json、marketplace.json）
skills/kb-starter/          skill 本体（安装这个）
├── SKILL.md                AI 读的工作流
├── scripts/kb.py           scan / decide / apply / verify / index / gaps / stats / lint / pack
├── references/             建库、蒸馏、入库与回流、体检的细则
└── templates/              入口文件、提示词和七种卡片模板
tests/                      测试用的是虚构课题（锂电池电解液），不含真实资料
├── make_fixtures.py        生成 50 个混合测试文件（含隐藏文件夹、iCloud 占位、无权限、多版本、同名文件）
├── e2e.py                  端到端测试（64 项断言）
└── 测试记录-20261016.md
```

运行测试：

```bash
python3 tests/e2e.py /tmp/kb-starter-test
```

## 已知限制

- 版本只按文件名末尾的标记识别（v2、修改版、终稿、(1)…）。内容几乎一样、但名字完全不同的两份稿子认不出来。
- 规则只看文件名、扩展名、DOI、EXIF 和文档标题，不读正文判断主题。没有 DOI 的中文期刊 PDF，要么靠所在文件夹名（“文献”“papers”等），要么交给 AI。
- 项目只能从文件夹名猜；散落在根目录的文件需要 AI 读内容后归组。
- 手机照片默认归“实验照片”（置信度标“中”，方案表里会提醒检查），生活照会被误判。
- 压缩包不解压，原样放进 `09_待定`。
- 体检的“候选概念”靠反复加粗的词和多处引用的空链接来找，仍有噪音，由 AI 再筛一遍。
- 只在 macOS 上测试过；Windows 路径未测试。
- 网页版 AI 不能运行 skill，只能用粘贴包读知识库，不能帮你写回。
