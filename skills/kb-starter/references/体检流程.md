# 体检流程细则

体检就是 Karpathy LLM Wiki 里的 lint：定期让 AI 自己通读，找出知识库里该改、该补、该问的地方。它是知识库在用户不派活时也会“长”的来源。

## 1. 拿事实清单

```
KB lint <知识库> --days 7 --out <工作目录>/lint.md
```

清单里有 10 节：近期改动、可能过时的项目总览、多处引用但没有页面的链接、反复加粗但没有节点的词、其他断链、没人链接的 B/C 层笔记、未登记的原始文件、整洁度、增长、纲要对照。前四节是写建议的主要线索。备份和 `历史*` 文件夹不参与检查。

第 9 节“增长”按周列出带标签的日志条数和新增卡片数，末尾有一句判断（例如“最近两周没有新增卡片，也没有蒸馏或回流：只在变大，没有在生长”）。这句判断要原样写进报告开头。知识索引过期时，体检后顺手运行 `KB index`。

## 2. 读近期改动

按清单第 1 节读近期改动的笔记，优先级：项目总览 > SOP/方案 > 实验记录 > 文献卡片 > 概念节点。批量改动的文件夹（例如一次重建的草稿）只抽看入口文件。

## 3. 写四类建议

按知识库里 `02_方法论库/AI提示词/知识库体检提示词.md` 的四类写，格式用 `模板_体检报告`。要点：

- **矛盾与过时**：最有价值的一类。重点查参数、条件、结论在不同笔记里是否一致；以最新的决策记录或总览为准，指出哪篇旧笔记要改哪一段。
- **该建的概念节点**：清单第 3、4 节是候选，你要筛掉格式性的词（如“步骤”“怎么用”），只保留真正的概念或方法。
- **假设状态变化**：对照假设台账和本周的实验记录、文献卡片。
- **下周 3 件事**：基于以上发现，而不是泛泛建议。

每条建议都要带来源链接；15 条以内；按重要性排序。

## 4. 等用户勾选

报告写到 `04_复盘日记/体检/YYYY-Www.md` 后告诉用户路径和最重要的 3 条。用户勾选、说“执行体检”后，只执行勾选的条目，按回流规则修改，并在变更日志记“执行体检 YYYY-Www 第 x、y 条”。

## 5. 效果怎么看

每期报告末尾统计上期建议的采纳数。一个月后看两个数：概念节点数量有没有稳定增长；建议采纳率。采纳率长期低于三成，说明建议太泛，下一期要更具体（必须指出具体笔记和段落）。

## 定时触发

用户想每周自动体检时，用宿主提供的定时任务（Claude 桌面版的 scheduled tasks、Claude Code 的 `/schedule`、系统 cron 调用命令行 AI 等），提示词写：“在 <知识库路径> 按 kb-starter 的体检流程做本周体检，只写报告不改笔记。”
