# 蒸馏流程细则

蒸馏就是把一次性的材料，变成以后还能直接用的知识卡片。知识库有没有“知识”，取决于这一步做没做。

## 材料 → 卡片

| 材料 | 蒸馏成 | 模板 | 放在 |
|---|---|---|---|
| 论文、标准、技术报告 | 文献卡片 | `模板_文献卡片` | `01_知识提炼/文献卡片/<项目>/` |
| 会议、聊天、邮件里定下的事 | 决策卡 | `模板_决策卡` | `01_知识提炼/决策/` |
| 解决过的故障、踩过的坑 | 问题卡 | `模板_问题卡` | `01_知识提炼/问题/` |
| 反复做的操作 | SOP | `模板_SOP` | `02_方法论库/SOP与方案/` |
| 经常打交道的人 | 人物卡 | `模板_人物卡` | `01_知识提炼/人物/` |
| 一个阶段结束后的复盘 | 教训卡 | `模板_教训卡` | `01_知识提炼/教训/` |
| 以上任何材料里反复出现的概念、方法 | 概念节点 | `模板_概念节点` | `01_知识提炼/概念节点/` |

一份材料可以产出几张卡。例如一次组会纪要：定下的实验条件写决策卡，导师的偏好补进人物卡，新冒出来的概念写进概念节点。

科研以外的工作也一样：客户会议 → 决策卡和人物卡；线上事故 → 问题卡；项目结项 → 教训卡；行业报告 → 文献卡片。

## 每张卡必须有的三个字段

卡片头部的这三个字段决定 AI 以后能不能想起它，`kb.py index` 靠它们生成知识索引：

- **一句话**：它说了什么。读完这一句，不打开卡片也能知道大意。
- **用于**：什么时候该想起它。写场景，不写主题。“设计添加剂浓度对照实验时”比“添加剂”好；“客户要求加急时”比“客户关系”好。
- **来源**：原文链接。没有来源的结论，以后无法核对。

## 怎么写

1. **区分原文和判断**：原文说的写“原文说”，带页码或时间点；你的推断写“我的判断”。不把推断写成原文结论。
2. **数字带单位和条件**：“容量保持率 92 %（0.5 C / 200 圈，n = 3）”，不写“强度不错”。
3. **原文引用只用短句**：卡片是自己的理解，不是原文复制。整段搬运既没用，也有版权问题。
4. **决策和问题要留原话**：谁说的、原话是什么，原样记下，再写自己的整理。
5. **写“和我的工作的关系”**：这一节决定卡片有没有用。说不出关系的材料，可以先不蒸馏。

## 蒸馏之后：回流三步

1. **更新概念节点**：这张卡里有 1–3 条会反复用到的结论，写进对应的概念节点（没有就新建），带上这张卡的链接。
2. **更新假设台账**：结果支持或否定了哪条假设，改状态。
3. **记日志、更新索引**：在变更日志里追加一行（格式见下），然后运行 `KB index`。没装本 skill 时，手动在 `知识索引.md` 的对应类型下加一行。

日志格式（标签写在行首，`stats` 按标签统计增长）：

```
- [蒸馏] [[原文文件名]] → [[新卡片]]；更新 [[概念节点]]（加入 XX 数据）
- [回流] 把 [[报告名]] 里的 3 条结论写回 [[概念A]]、[[概念B]]
- [决策] 导师确认截止电压改为 4.4 V → [[决策 · 截止电压 4.4 V]]
```

## 什么时候蒸馏

- **入库之后**：新文献、新会议记录入库后，问用户要不要现在蒸馏，用户同意再做。
- **任务需要时**：做任务时发现要用的知识只在原文里，先蒸馏成卡片再用。下次就不用再读原文了。
- **缺口自检之后**：按 `缺口清单.md` 里勾选的条目蒸馏。

不要一次蒸馏全部原文。几百篇参考文献里，真正会反复用到的通常只有几十篇；先蒸馏缺口自检认为最缺的那些。

## 已有专业精读 skill 时

环境里装了更专业的论文精读 skill（如各类 paper-card、paper-reader），可以用它生成正文，但卡片头部仍要补上「类型 / 一句话 / 用于 / 来源 / 项目」，并加上“与我的工作的关系”和“回流”两节，否则知识索引里看不到它。kb-starter 不依赖任何外部 skill。
