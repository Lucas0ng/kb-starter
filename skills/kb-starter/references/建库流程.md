# 建库流程细则

## 方案表 plan.csv

| 列 | 含义 |
|---|---|
| id | 编号，decisions.json 用它定位 |
| 状态 | `复制`：将复制入库；`待AI`：需要你判断；`跳过`：系统文件、空文件、重复文件、隐藏文件夹；`已入库`：知识库里已有相同内容；`登记`：文件已在知识库目录内，只记入清单；`无法读取`：iCloud 未下载、没有权限、失效链接，不入库但必须告诉用户 |
| 类别 | 见下表 |
| 项目 | 项目或课程名，可为空 |
| 子目录 | 目标目录下再加的一层：`历史版本`（旧版本），或同名文件的来源文件夹名 |
| 入库名 | 给看不出内容的文件起的新名字，只用于知识库里的副本；空 = 用原名 |
| 目标目录 | 由类别、项目、子目录自动算出，不用手改 |
| 依据 | 为什么这样分 |
| 置信度 | 高 / 中 / 低 / AI |
| 修改时间、sha256 | 对账用，不要改 |

用户可以直接在 Excel 里改「状态」「类别」「项目」「子目录」「入库名」，保存为 CSV 即可：UTF-8、Windows 版 Excel 直接保存的 GBK 都能读；Excel 把修改时间的小数位丢掉也不影响对账。名字以 `/` 结尾的行是未展开的文件夹（隐藏、依赖、符号链接），依据里写明含多少个文件。

## 三项保证怎么实现

| 保证 | 做法 | 怎么验证 |
|---|---|---|
| 原件完好 | 只用复制（保留时间戳），从不移动、改名、删除来源文件；改名只发生在副本上 | 对账比对原件修改时间；`verify --full` 重算原件哈希 |
| 一个不漏 | 每个文件一行；隐藏和依赖文件夹记一行并写明文件数；读不了的单独标出；`待AI` 没清零时 apply 拒绝执行 | 对账重新遍历来源，等式“来源总数 = 复制 + 登记 + 已入库 + 跳过 + 无法读取 + 未展开文件夹内”必须成立；扫描后新增或消失的文件会被列出 |
| 副本一致 | 每个副本按哈希登记进 `.kb/manifest.csv` | 对账逐个重算副本哈希 |
| 整理完不乱 | 固定分层 + 项目子目录；旧版本进 `历史版本/`；同名文件保留来源文件夹；无意义文件名可起入库名；新项目名会提示合并到已有项目 | 每周体检第 8 节“整洁度” |

每次 apply 的方案表、扫描信息和对账单都存档在 `.kb/plans/`，以后可以对任何一次入库重新 `verify`。

## 类别

| 类别 | 目标目录 | 典型文件 |
|---|---|---|
| 论文 | `00_原始资料/01_论文原文/<项目>` | 期刊论文、预印本、学位论文 PDF |
| 题录 | 同上 | .bib .ris .enw |
| 源稿 | `00_原始资料/01_论文原文/<项目>/源稿` | 导师或合作者给的、待修改的稿子 |
| 实验记录 | `00_原始资料/02_实验记录/<项目>` | 方案原稿、记录单、表格数据、仪器数据 |

| 个人笔记 | `00_原始资料/06_个人笔记/<项目>` | 用户以前写的零散笔记 |

## decisions.json

```json
{
  "rename_projects": {"electrolyte": "电解液", "电解液实验": "电解液"},
  "items": {
    "5":  {"类别": "论文", "项目": "电解液", "依据": "首页是期刊论文，CNKI 下载，无 DOI"},
    "8":  {"类别": "汇报PPT", "项目": "电解液", "依据": "前三页是本人组会汇报"},
    "30": {"入库名": "20261013_扣电组装", "依据": "照片是第 3 批扣式电池组装"},
    "12": {"子目录": "", "依据": "不是旧版本，是另一份申请书"},
    "17": {"状态": "跳过", "依据": "与研究无关的生活截图"},
    "21": {"类别": "待定", "依据": "扫描件无法识别内容，留给用户"}
  }
}
```

- `items` 的键是 plan.csv 的 id（字符串）。
- 给了「类别」而没给「状态」时，待AI条目自动变成「复制」。
- `rename_projects` 对整张表生效，用来合并项目名。
- 「类别」必须是上表中的一个，否则 decide 会报错并列出可选值。
- 「入库名」不能带路径、不能改扩展名（省略扩展名会自动补上）。
- 「子目录」可以用来纠正版本判断：脚本把不是旧版本的文件放进了 `历史版本`，就写 `"子目录": ""`。
- decide 之后会重新检查版本组和同名冲突（归组项目后可能出现新的）。

## 判断待AI条目的要点

- **别人的还是自己的**：这是最常见的难点。看作者栏、页眉页脚、修订痕迹、是否有期刊排版。期刊排版 → 论文；Word 稿且作者是用户 → 论文草稿；Word 稿作者是导师或他人、内容是用户的课题 → 源稿。
- **截图**：直接看图。论文截图 → 论文（或待定）；聊天记录里的导师意见 → 会议记录；仪器界面 → 实验记录；无关内容 → 跳过（需在汇报中列出）。
- **幻灯片**：前几页有课程名、章节号、老师名 → 课程资料；有用户姓名、组会、日期 → 汇报PPT。
- **项目归属**：只用纲要里的项目名。看文件里出现的课题名、样品名、课程名，对照纲要各项目的目标和关键词；实在看不出就留空，并在汇报里说明。同一类文件反复看不出归属时，说明纲要缺关键词：补进纲要再扫一次。
- **拿不准就选「待定」**，不要猜。09_待定 里的文件以后体检时会被提醒。

## 已有知识库

如果知识库路径已存在：

- 有 `.kb/manifest.csv`：是 kb-starter 建的库，直接按入库流程走。
- 没有 `.kb/`：先问用户是并入还是另建。并入时 apply 不会覆盖已有的同名入口文件（导航、说明等），只补缺失的目录和模板；已有文件可以用 `scan <知识库>/00_原始资料 --kb <知识库>` 登记。

## 整理规则：先整理，后审查

知识库根目录的 `整理规则.md` 分两半：

- **你的规则**（上半）：一张表，用户的纠正都写在这里。`scan` 和 `reorg` 都先按它来，优先级高于所有内置规则、纲要关键词，也高于隐私提醒（用户写了规则，就是用户的决定）。
- **最近一次整理用到的规则**（下半）：每次 `apply` 自动重写，把这次的分类归纳成五节，编号方便用户指着说：
  - **A. 先看这几条**：你逐个判断的、两个项目打平的、放进待定的、疑似隐私没入库的、读不了的。
  - **B. 分类规则**：例如“PDF 里有 DOI → 论文（12 个）”“文件名含「slides」→ 汇报PPT（把握一般，3 个）”。
  - **C. 项目规则**：文件夹名、纲要关键词、你的判断各分到哪个项目；“没有归到任何项目”也列出来。
  - **D. 不入库**：系统文件、空文件、重复文件、未展开的文件夹。
  - **E. 版本、同名与改名**。

### 你的规则怎么写

| 列 | 写什么 |
|---|---|
| 匹配 | 文件名或文件夹名里包含的文字，不分大小写；含 `*` `?` 时按通配符匹配，如 `IMG_*.jpg` |
| 看哪里 | `文件名` / `文件夹` / `路径`（空着 = 路径：文件夹名和文件名都看）。路径指相对资料文件夹的路径 |
| 归为 | 一个类别，或 `不入库`；空着表示只改项目 |
| 项目 | 纲要里的项目名；空着表示不改项目 |
| 为什么 | 用户的原话或理由，给以后的人和 AI 看 |

从上往下，第一条匹配的规则生效。类别写错的行会被跳过并提示。

把用户的意见翻译成规则时：

- “B17 不对，slides 是课件” → `| slides | 文件名 | 课程资料 | 高分子物理 | slides 开头的都是课件 |`
- “张老师给的都是电解液的” → `| 张老师给的 | 文件夹 | | 电解液 | 张老师给的是电解液参考资料 |`
- “微信图片都不要” → `| 微信图片_* | 文件名 | 不入库 | | 聊天截图不入库 |`
- “A3 那个是会议记录” → 只涉及一个文件，匹配写完整文件名：`| 导师修改意见.docx | 文件名 | 会议记录 | 电解液 | 刘老师的修改意见 |`

### reorg 做什么

`KB reorg <知识库>` 对清单里每个副本（用户手动放进知识库、只登记的文件除外）按「你的规则」重新算一次类别和项目：

- 变了就把副本挪到新目录，`历史版本/`、同名来源文件夹这些子目录跟着保留；
- 「归为」是 `不入库` 的，副本移到 `.kb/回收/<时间>/`（可以手动恢复），从清单删掉，并记进不入库清单，以后扫描也不再入库；
- 更新清单、资料索引，把笔记里指向这些文件的 `[[链接]]` 改成新路径，变更日志记一行 `[整理]`；
- 原件不动。之后 `verify` 仍然通过，移出的文件算“按整理规则移出”。

先用 `--dry-run` 看会挪哪些，确认范围符合用户的意思再执行。

## 纲要怎么参与分项目

扫描时脚本读 `<知识库>/知识库纲要.md`（或 `--outline` 指定的文件），按下面的顺序给每个文件定项目，依据写在方案表里：

1. 文件所在的某一层文件夹名等于纲要里的项目名或别名 → 归到这个项目（置信度不变）。
2. 文件名、所在文件夹名、文档标题和首页文字里出现某个项目的关键词 → 归到命中最多的项目；文件名里的命中算两次。两个项目打平时不归，依据里写“关键词同时命中「A」「B」”，由你判断。
3. 都没命中 → 保留按文件夹名猜的项目，依据里标“文件夹名「X」不在纲要里”；plan.md 的“识别到的项目”会把它列在“不在纲要里的项目名”下，由你并入纲要项目或问用户要不要新增。

plan.md 的“识别到的项目”按纲要顺序列出每个项目分到了几个文件；分到 0 个的项目也会列出来，可能是关键词不对，也可能是用户确实还没有这个项目的资料。

## 项目总览草稿怎么写

先运行 `KB overview <知识库>`。它为纲要里的每个项目生成一份草稿：

- **【你定】的段落**（一句话目标、核心问题、你说的当前状态）照抄纲要。你不要改写；资料和它不一致时写进“待确认”。
- **【AI 整理】的段落**脚本先填一部分：资料概况（每类几个文件、最近一份是哪个）、最近 5 份记录、每类最新的文件作为“现行文件候选”。

你接着补全：

- **资料显示的进展**：读“最近的记录”里的文件，写“截至 YYYY-MM-DD 资料显示……”。
- **现行执行文件**：从候选里选出每个步骤真正在用的那份，写清当前口径（关键参数、条件）。同一主题有多个版本时，列最新的，其余在“待确认”里请用户确认。
- **待确认**：纲要和资料说法不一致的、版本不知道哪个算数的、总览需要但资料里没有的，逐条列出。

总览已经存在时，脚本不覆盖，草稿写到 `99_工作区/总览草稿/`，你对照着把新信息合并进现有总览。
