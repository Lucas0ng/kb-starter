# 知识库说明

> [!important] 给 AI 的话
> 要新增、移动、分类文件，或者要写新笔记时，按本说明执行。本说明是这个知识库唯一的规则来源；[[知识库导航]] 和 `AGENTS.md` 只是入口。

## 工作方式

按“**原始资料 → 提炼 → 用户确认 → 正式交付 → 回流**”工作。不要只把知识库当聊天背景：读已有笔记，产出实际文件，并把以后还会用到的知识写回 B/C 层。

## 主线：知识库纲要

[[知识库纲要]] 写着这个知识库为什么存在、有哪些项目、每个项目要回答什么问题，以及用来把资料分到项目的关键词。它由用户定：

- 资料属于哪个项目、什么值得蒸馏、总览怎么写，都以纲要为准。
- 项目总览里标【你定】的段落来自纲要；标【AI 整理】的段落由 AI 从资料整理、用户确认。
- 纲要过时了（项目阶段变了、出现新方向、核心问题有了答案），AI 在体检时提议修改，用户勾选后才改，并在纲要的「修订记录」里记一行。

## 新文件放哪

先问一句：**这是别人给我的输入，还是我做出来的产出？**

| 你手上的文件 | 放进 |
|---|---|
| 下载的文献 PDF、题录 | `00_原始资料/01_论文原文/<项目>/` |
| 别人给的待改稿 | `00_原始资料/01_论文原文/<项目>/源稿/` |
| 实验方案原稿、记录、数据、现场照片 | `00_原始资料/02_实验记录/<项目>/` |
| 会议录音、转写、纪要 | `00_原始资料/03_会议记录/<项目>/` |
| 网页剪藏 | `00_原始资料/04_网页剪藏/` |
| 课件、作业、课程笔记 | `00_原始资料/05_课程笔记/<课程>/` |
| 以前的个人笔记 | `00_原始资料/06_个人笔记/` |
| 暂时判断不了的 | `00_原始资料/09_待定/` |
| 我写的论文稿 | `03_研究输出/论文草稿/<项目>/` |
| 我做的汇报 PPT | `03_研究输出/汇报PPT/<项目>/` |
| 我写的报告、申请书 | `03_研究输出/报告/<项目>/` |
| AI 过程文件、脚本、中间结果 | `99_工作区/` |
| 临时想法 | 写进 [[INBOX]]，有空再归位 |

B 层（`01_知识提炼/`）和 C 层（`02_方法论库/`）不手动塞文件，它们由 AI 在任务中从 A、D 层提炼出来。

## 知识卡片：把材料蒸馏成知识

原始资料只是材料，知识在卡片里。按材料类型选模板（都在 `02_方法论库/写作模板/`）：

| 材料 | 蒸馏成 | 放在 |
|---|---|---|
| 论文、标准、报告 | 文献卡片 | `01_知识提炼/文献卡片/` |
| 会议、聊天、邮件里定下的事 | 决策卡 | `01_知识提炼/决策/` |
| 解决过的故障、踩过的坑 | 问题卡 | `01_知识提炼/问题/` |
| 反复做的操作 | SOP | `02_方法论库/SOP与方案/` |
| 经常打交道的人 | 人物卡 | `01_知识提炼/人物/` |
| 阶段复盘 | 教训卡 | `01_知识提炼/教训/` |
| 反复出现的概念、方法 | 概念节点 | `01_知识提炼/概念节点/` |

每张卡头部必须有三个字段：**一句话**（说了什么）、**用于**（什么时候该想起它，写场景不写主题）、**来源**（原文链接）。[[知识索引]] 由这三个字段生成，AI 每次开工先读索引，靠「用于」把当前任务和过去的知识对上。

## 回流：每次任务结束必做

1. 新文件按上表落位。
2. **蒸馏**：这次用到或得到的、以后还会用的知识写成卡片。
3. **写回概念节点**：1–3 条会反复用到的结论写进概念节点。已有节点就更新对应段落，没有就按 [[模板_概念节点]] 新建。每条结论带来源链接。
4. **更新假设台账和缺口清单**：结果支持、否定了哪条假设，改 [[假设台账]]；补上了哪个缺口，在 [[缺口清单]] 里勾掉。
5. 受影响的项目总览、SOP 同步更新。
6. **记日志、更新索引**：在 [[知识库变更日志]] 追加带标签的一行，再更新 [[知识索引]]。

纯问答和只读分析不触发回流。

> [!tip] 为什么要这样
> 知识库能“自己长”，靠的是每次任务都留下可复用的卡片，而不是只留下成品。概念节点是生长的基本单位；文献、决策、问题卡片和报告都是它的来源。

## 缺口：缺知识时不凭空补

做任务时发现缺少某项知识，AI 不凭空补，而是在 [[缺口清单]] 的“待补”下记一条：缺什么、哪个任务需要、建议去哪补、补上后能回答什么。开始一件大事之前，用 `02_方法论库/AI提示词/缺口自检提示词.md` 让 AI 主动列出还缺什么。

## 日志：每行带类型标签

[[知识库变更日志]] 每条记录行首写一个标签，用来统计知识库是在“生长”还是只在“变大”：

| 标签 | 什么时候用 |
|---|---|
| `[入库]` | 新文件放进知识库 |
| `[蒸馏]` | 原文写成了卡片，写成`[[原文]] → [[卡片]]` |
| `[回流]` | 结论写回了概念节点、SOP 或假设台账 |
| `[缺口]` | 新记了缺口，或补上了缺口 |
| `[体检]` | 做了体检，或执行了体检建议 |
| `[决策]` | 记下了一个新决定 |
| `[整理]` | 移动、改名、归档、清理 |

## 笔记怎么写

- **项目总览只写“现在”**：当前状态、现行文件表、待确认事项。历次进展原文进 `04_复盘日记/<项目>_进展时间线`。
- **SOP 现行操作置顶**：修订后直接改写页首的“现行操作”，旧口径整段移到页末“历史口径与修订记录”。
- **旧版本下沉不删除**：被替代的文件移入同目录 `历史版本/`。
- **根目录只放入口**：纲要、整理规则、导航、说明、变更日志、知识索引、INBOX、AGENTS.md、CLAUDE.md 和各项目总览。
- **分错了就改规则**：文件分错类、分错项目时，不要手动挪，在 [[整理规则]] 的「你的规则」里加一行，再让 AI 运行 `reorg`。这样以后入库也会照这条规则来。
- **区分事实和推断**：实验记录分“原话 / 实测 / 计算 / 推断”；没有来源写“资料未提供”，不确定写“待确认”。
- **文件命名**：正式成果用 `YYYYMMDD-主题-v1.ext`，修改递增版本号，不覆盖旧版。
- 新笔记从 `02_方法论库/写作模板/` 里的模板开始写。

## 每周体检

每周一次，按 `02_方法论库/AI提示词/知识库体检提示词.md` 执行，报告写到 `04_复盘日记/体检/YYYY-Www.md`。体检只提建议；用户勾选后，AI 再执行被勾选的项目。

## 禁止事项

- 不覆盖、重命名、移动或删除 `00_原始资料/` 中的文件，除非用户明确要求。
- 不把未确认稿、测试文件或一次性分析混入正式成果和知识层。
- 不保存密码、Token、API Key 等凭据。
- 没有来源时不补造数据、引用或结论。
